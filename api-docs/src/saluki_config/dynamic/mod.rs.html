1//! Dynamic configuration.
2//!
3//! A configuration producer publishes [`ConfigSetting`]s over a stream of [`ConfigUpdate`]s. Two
4//! things consume that stream. A caller wanting a live by-key view hands the receiver to
5//! [`ConfigurationLoader::with_dynamic_configuration`][crate::ConfigurationLoader::with_dynamic_configuration],
6//! which keeps a [`GenericConfiguration`][crate::GenericConfiguration] current and reports each change
7//! through [`ConfigChangeEvent`] or a [`FieldUpdateWatcher`]. A caller wanting its own representation
8//! takes [`ConfigSetting`] and [`ConfigUpdate`] alone and folds them itself.
9
10// The by-key view has no consumer in this repository: `agent-data-plane` folds the stream into its own
11// typed model and takes only `ConfigSetting`, `ConfigUpdate` and `Provenance` from this module. The
12// view is kept because this crate is general-purpose infrastructure and the by-key path is the
13// cheapest way for another process to consume a configuration stream. Until it has a consumer, the
14// unit tests in this module and in `crate` are the only thing exercising it, so do not thin them out.
15
