1//! Builder for describing children.
2//!
3//! [`ChildSpecification`] is the complete description of a child, and this builder is the only way to configure one:
4//! the specification itself carries no public methods. The builder turns an asynchronous function, or a
5//! [`Supervisable`], into a child with sensible defaults, and uses the typestate pattern to expose only the settings
6//! that make sense for the kind of worker being described.
7//!
8//! The builder has an ambient form and an explicit form, one for each of the two ways to spawn. The free functions in
9//! this module ([`worker`], [`supervisable`]) spawn into the current process. The methods with the same names on
10//! [`SupervisorHandle`] spawn onto the supervisor of that handle. In both forms, [`ChildBuilder::spawn`] starts the
11//! child. [`ChildBuilder::build`] gives the child to [`Supervisor::add_worker`][add_worker], and the supervisor starts
12//! the child when it runs.
13//!
14//! [add_worker]: super::Supervisor::add_worker
15//!
16//! # Restart policy
17//!
18//! You do not choose the restart policy of a child directly. The policy follows from two facts: whether the child can
19//! be started again, and whether its owner can work without it. See the [runtime documentation][restart] for how the
20//! policy is derived, and for the defaults.
21//!
22//! [restart]: super#restart-policy
23//!
24//! # Shutdown
25//!
26//! A subtree shutdown is a _trigger_, not an enforcement. A one-shot child built with [`worker`] never receives the
27//! shutdown signal. It runs until it reaches its own terminal condition, and its owner waits for it. Examples of a
28//! terminal condition are an input channel that closes, a loop that finishes, and a request that completes.
29//!
30//! This behavior lets a set of tasks that are connected by channels drain in dependency order. The tasks do not have to
31//! know that order. Because of this behavior, it is not a problem that a one-shot child cannot see the shutdown signal.
32//!
33//! Each child is held to its own shutdown strategy, whether its owner is a supervisor or a scope. A closure-based child
34//! is graceful, with a timeout of five seconds. When a timeout expires, the process is halted along with everything in
35//! its scope.
36//!
37//! Two cases need something other than the default:
38//!
39//! - Work with no terminal condition holds the drain open until its timeout expires. An endless background loop is an
40//!   example. Give it [`ShutdownStrategy::Brutal`] with [`ChildBuilder::with_shutdown_strategy`] so that it is halted
41//!   at once.
42//! - If work must observe shutdown to know that it must stop, or must run cleanup, build it with
43//!   [`worker_with_shutdown`]. The body of that worker receives the shutdown signal. You can also implement
44//!   [`Supervisable`] directly.
45//!
46//! [`ChildBuilder::with_shutdown_timeout`] sets a timeout other than the default. Use it if a particular child needs
47//! more time to drain, or must be halted sooner than its siblings.
48//!
49//! # Children of the current process
50//!
51//! [`ChildBuilder::spawn`] makes a child a child of the current process, and the [scope][super::scope] of that process
52//! holds it. The process does not finish until its children finish. When the body of the process returns, the scope
53//! stops the children, each according to its own shutdown strategy. [`ChildBuilder::spawn_sibling`] gives the child
54//! to the nearest supervisor above the current process instead.
55//!
56//! # Task naming
57//!
58//! Child task names should generally _not_ contain unique patterns/tokens -- such as monotonic IDs or high-cardinality
59//! values -- as they are used for internal telemetry about the task. Generally, task names should be thought of as a
60//! category label: if a supervisor manages tasks for handling connections, it should prefer to name them like
61//! `conn_handler` instead of `conn_handler_<ID or IP>`.
62

248/// Marks a builder whose worker can only be started once.
249///
250/// Closure-based children ([`SupervisorHandle::worker`]) consume their body when they start, so they can never be
251/// restarted.
252pub struct OneShot;
253
254/// Marks a builder whose worker can usually be started more than once.
255///
256/// A [`Supervisable`] builds its work in [`initialize`][Supervisable::initialize] each time it starts, so it can be
257/// restarted. A [`Supervisable`] that consumes something when it starts says so through
258/// [`can_restart`][Supervisable::can_restart], and its owner never restarts it.
259pub struct Restartable;

266/// Builder for a yet-to-be-started child task.
267///
268/// This is the only way to configure a child: [`ChildSpecification`], which this produces, carries no settings of its
269/// own. The builder uses the typestate pattern to expose only the properties that apply to the child that it describes.
270/// See [`BuilderState`] for the states.
271#[must_use = "a child is only described until `spawn` or `build` is called"]
272pub struct ChildBuilder<'a, S = OneShot> {
273    target: BuilderTarget<'a>,
274    spec: ChildSpecification<WorkerSpec>,
275    _state: PhantomData<S>,
276}
277
278/// The place where a [`ChildBuilder`] spawns its child.
279#[derive(Clone, Copy)]
280enum BuilderTarget<'a> {
281    /// The scope of the current process, or the ambient supervisor if there is no current scope.
282    Ambient,
283
284    /// This specific supervisor.
285    Handle(&'a SupervisorHandle),
286}
287
288impl<'a, S: BuilderState> ChildBuilder<'a, S> {
289    fn new(target: BuilderTarget<'a>, spec: ChildSpecification<WorkerSpec>) -> Self {
290        Self {
291            target,
292            spec,
293            _state: PhantomData,
294        }
295    }
296
297    fn map_spec<F>(self, f: F) -> Self
298    where
299        F: FnOnce(ChildSpecification<WorkerSpec>) -> ChildSpecification<WorkerSpec>,
300    {
301        let Self { target, spec, .. } = self;
302
303        Self::new(target, f(spec))
304    }
305
306    /// Runs this child task on a specific runtime.
307    ///
308    /// Use this method for compute-heavy work that must not compete with the runtime that drives its owner and its I/O.
309    /// Examples are encoding, serialization, and protocol servers. This method changes only where the task runs. The
310    /// owner of the child still supervises, shuts down, and restarts the child.
311    pub fn on_runtime(self, handle: Handle) -> Self {
312        self.map_spec(|spec| spec.with_runtime(handle))
313    }
314
315    /// Sets an explicit shutdown timeout for this child task.
316    ///
317    /// A closure-based child defaults to five seconds, after which it is halted. Set this if a particular child needs
318    /// more time to drain, or must be halted sooner. A timeout longer than its owner's has no effect, since the child
319    /// is halted along with its owner.
320    ///
321    /// For a [`Supervisable`] child, this overrides the strategy the task reports for itself.
322    pub fn with_shutdown_timeout(self, timeout: Duration) -> Self {
323        self.with_shutdown_strategy(ShutdownStrategy::Graceful(timeout))
324    }
325
326    /// Sets the explicit shutdown strategy used for this child task.
327    pub fn with_shutdown_strategy(self, strategy: ShutdownStrategy) -> Self {
328        self.map_spec(|spec| spec.with_shutdown_strategy(strategy))
329    }
330
331    /// Marks this child as one that its owner cannot work without.
332    ///
333    /// If the child stops without a request to stop and can only be started once, its owner also stops and fails. This
334    /// occurs even when the child exits cleanly. Thus, use this method for a child that its owner cannot work without.
335    /// Do not use it for a child that you expect to finish by itself. If the child can be started again, its owner
336    /// restarts it after any such stop, not only after a failure.
337    ///
338    /// For example, one failed connection is usually not a reason to stop a component that handles client connections.
339    /// But a component that forwards work to a child task can become inoperable if that task stops unexpectedly. This
340    /// occurs if the task cannot be attached again to the necessary channels or state unless the component is created
341    /// again.
342    ///
343    /// See the [runtime documentation][super#restart-policy] for the default.
344    pub fn needed(self) -> Self {
345        self.map_spec(|spec| spec.with_edge(Edge::Needed))
346    }
347
348    /// Marks this child as one that its owner runs but does not need.
349    ///
350    /// If the child stops without a request to stop, and its owner does not restart it, the owner reaps the child and
351    /// continues. The owner does not restart a child that can only be started once, or a child that exited cleanly. If
352    /// the child can be started again, its owner restarts it only if it failed, and accepts a clean exit as final. But
353    /// if the child fails more often than the restart limit of its owner allows, the owner also fails, as for a needed
354    /// child.
355    ///
356    /// See the [runtime documentation][super#restart-policy] for the default.
357    pub fn hosted(self) -> Self {
358        self.map_spec(|spec| spec.with_edge(Edge::Hosted))
359    }
360
361    /// Sets whether the supervisor stops when this child task terminates.
362    ///
363    /// This setting has an effect only under a supervisor that uses the deprecated
364    /// [`with_auto_shutdown`][super::Supervisor::with_auto_shutdown]. It also has no effect on a child that its
365    /// supervisor always restarts, such as a child that can start again and that you declare with
366    /// [`Supervisor::add_worker`] without marking it [hosted][Self::hosted]. The supervisor logs a warning for each
367    /// child where the setting has no effect.
368    #[deprecated(note = "mark the child `needed` instead, which stops its owner when it terminates for good")]
369    pub fn with_significant(self, significant: bool) -> Self {
370        self.map_spec(|spec| spec.with_significant(significant))
371    }
372
373    /// Makes this child adopt `scope` as its own and start what was spawned into it before the child started.
374    pub(crate) fn adopting(self, scope: UnadoptedScope) -> Self {
375        self.map_spec(|spec| spec.adopting(scope))
376    }
377
378    /// Gives this child a resource group of its own, with the same name as the child.
379    ///
380    /// The child then does not count against the resource group of its owner. Use this for a worker that represents
381    /// something with its own resource accounting, such as a topology component.
382    pub(crate) fn with_own_resource_group(self) -> Self {
383        self.map_spec(|spec| spec.with_own_resource_group())
384    }
385
386    /// Makes `observer` receive how this child ended, after its scope closed. See [`ExitObserver`].
387    #[cfg(any(test, feature = "test-util"))]
388    pub(crate) fn observing_exit(self, observer: ExitObserver) -> Self {
389        self.map_spec(|spec| spec.observing_exit(observer))
390    }
391
392    /// Finishes describing the child without starting it, for [`Supervisor::add_worker`].
393    ///
394    /// Use this method to register a configured child on a supervisor that has not started yet. The supervisor starts
395    /// this child when it runs. When the supervisor restarts, the child restarts with it. To start a child now, use
396    /// [`spawn`][Self::spawn].
397    ///
398    /// Whichever supervisor this builder was created against is irrelevant here -- the child belongs to whichever one
399    /// it is handed to.
400    ///
401    /// [`Supervisor::add_worker`]: super::Supervisor::add_worker
402    pub fn build(self) -> ChildSpecification<WorkerSpec> {
403        self.spec
404    }
405
406    /// Spawns the child.
407    ///
408    /// A builder that was created from a [`SupervisorHandle`] spawns the child onto that supervisor. Other builders
409    /// make the child a child of the current process, and the [scope][super::scope] of that process holds it. See
410    /// [`spawn`][super::spawn].
411    ///
412    /// Returns the [`ChildId`] of the child. This method queues the child and does not start it synchronously. Thus,
413    /// when this method returns, the child can still be in the queue. If its owner does not run, or stops before it
414    /// processes the child, the child never runs.
415    ///
416    /// # Panics
417    ///
418    /// Panics if this builder does not target a specific supervisor and code outside supervision calls this method. See
419    /// [`spawn`][super::spawn].
420    pub fn spawn(self) -> ChildId {
421        let Self { target, spec, .. } = self;
422
423        match target {
424            BuilderTarget::Ambient => super::spawn(spec),
425            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
426        }
427    }
428
429    /// Spawns the child onto the ambient supervisor, the nearest supervisor above the current process.
430    ///
431    /// The child is a sibling of the current process only if a supervisor runs that process directly. For a process
432    /// that runs in a scope, the child goes to the nearest supervisor above it instead. See
433    /// [`spawn_sibling`][super::spawn_sibling].
434    ///
435    /// A builder that was created from a [`SupervisorHandle`] spawns the child onto that supervisor, exactly as
436    /// [`spawn`][Self::spawn] does.
437    ///
438    /// # Panics
439    ///
440    /// Panics if this builder does not target a specific supervisor and there is no ambient supervisor.
441    pub fn spawn_sibling(self) -> ChildId {
442        let Self { target, spec, .. } = self;
443
444        match target {
445            BuilderTarget::Ambient => super::spawn_sibling(spec),
446            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
447        }
448    }
449
450    /// Spawns the child into `scope`.
451    pub fn spawn_in(self, scope: &Scope) -> ChildId {
452        let Self { spec, .. } = self;
453
454        scope.spawn(spec)
455    }
456
457    /// Spawns the child into the scope of the current process, or as a detached task outside supervision.
458    ///
459    /// Returns the [`ChildId`] of the child, or `None` if there was no current scope and the child started as a
460    /// detached task instead. A detached child never receives a shutdown signal, and nothing restarts it or waits for
461    /// it. This is how the same work runs without supervision at all. Thus, this method is the correct choice for code
462    /// that can be called from any location, such as a primitive that a test can construct.
463    pub fn spawn_or_detached(self) -> Option<ChildId> {
464        let Self { spec, .. } = self;
465
466        match scope::current() {
467            Some(scope) => Some(scope.spawn(spec)),
468            None => {
469                scope::spawn_detached(spec, ShutdownHandle::noop());
470                None
471            }
472        }
473    }
474}

508/// Builder for a yet-to-be-started nested supervisor.
509///
510/// The counterpart to [`ChildBuilder`] for a child that is itself a [`Supervisor`], and deliberately a much smaller
511/// surface. A nested supervisor has no placement of its own, because it runs where its parent runs and its children
512/// carry their own placement. It also has no shutdown deadline of its own, because it limits its own drain through its
513/// children. Thus, the settings that remain are whether it is needed or hosted, and whether it stops with its owner.
514#[must_use = "a child is only described until `spawn` or `build` is called"]
515pub struct NestedSupervisorBuilder<'a> {
516    target: BuilderTarget<'a>,
517    spec: ChildSpecification<SupervisorSpec>,
518}
519
520impl<'a> NestedSupervisorBuilder<'a> {
521    fn new(target: BuilderTarget<'a>, supervisor: Supervisor) -> Self {
522        Self {
523            target,
524            spec: ChildSpecification::from(supervisor),
525        }
526    }
527
528    fn map_spec<F>(self, f: F) -> Self
529    where
530        F: FnOnce(ChildSpecification<SupervisorSpec>) -> ChildSpecification<SupervisorSpec>,
531    {
532        let Self { target, spec } = self;
533
534        Self { target, spec: f(spec) }
535    }
536
537    /// Marks this subtree as one that its owner cannot work without.
538    ///
539    /// See [`ChildBuilder::needed`], which this method mirrors.
540    pub fn needed(self) -> Self {
541        self.map_spec(|spec| spec.with_edge(Edge::Needed))
542    }
543
544    /// Marks this subtree as one that its owner runs but does not need.
545    ///
546    /// See [`ChildBuilder::hosted`], which this method mirrors.
547    pub fn hosted(self) -> Self {
548        self.map_spec(|spec| spec.with_edge(Edge::Hosted))
549    }
550
551    /// Tells this subtree to stop as soon as its owner is told to stop, instead of when the owner's scope closes.
552    ///
553    /// Use this for ingress whose output the owner's body consumes, such as a server whose handlers feed a channel that
554    /// the body drains. The server stops accepting work and finishes what it accepted while the body keeps draining.
555    ///
556    /// This takes effect only in the scope of a worker that takes the shutdown signal (see
557    /// [`Supervisable::wants_shutdown_signal`]). A supervisor tells all of its children to stop at once anyway, and a
558    /// worker that takes no signal has nothing to stop the subtree with.
559    ///
560    /// The scope keeps the subtree's specification until the subtree exits, and the specification holds whatever the
561    /// subtree was built with, such as the sender in a request handler. Thus, the channel closes once the subtree exits.
562    /// The body **MUST NOT** hold a sender of that channel itself, or the channel never closes. See the
563    /// [scope documentation][super::scope#nested-supervisors-that-stop-with-their-owner].
564    pub fn stops_with_owner(self) -> Self {
565        self.map_spec(|spec| spec.stopping_with_owner())
566    }
567
568    /// Restarts this subtree only when it terminates abnormally.
569    #[deprecated(note = "mark the subtree `hosted` instead, which restarts it only if it fails")]
570    pub fn transient(self) -> Self {
571        self.map_spec(|spec| spec.with_restart_type(RestartType::Transient))
572    }
573
574    /// Never restarts this subtree.
575    #[deprecated(note = "a supervisor can always be started again; mark it `hosted` or `needed` instead")]
576    pub fn temporary(self) -> Self {
577        self.map_spec(|spec| spec.with_restart_type(RestartType::Temporary))
578    }

580    /// Sets whether the parent supervisor stops when this subtree terminates.
581    #[deprecated(note = "mark the subtree `needed` instead, which stops its owner when it terminates for good")]
582    pub fn with_significant(self, significant: bool) -> Self {
583        self.map_spec(|spec| spec.with_significant(significant))
584    }

586    /// Finishes describing the child without starting it, for [`Supervisor::add_worker`].
587    ///
588    /// Use this method to register a configured subtree on a supervisor that has not started yet. To start the subtree
589    /// now, use [`spawn`][Self::spawn].
590    ///
591    /// Whichever supervisor this builder was created against is irrelevant here -- the child belongs to whichever one
592    /// it is handed to.
593    pub fn build(self) -> ChildSpecification<SupervisorSpec> {
594        self.spec
595    }
596
597    /// Spawns the nested supervisor.
598    ///
599    /// This method works as [`ChildBuilder::spawn`] does. It spawns onto the target supervisor if the builder has one.
600    /// If not, it spawns the nested supervisor as a child of the current process.
601    ///
602    /// # Panics
603    ///
604    /// Panics if this builder does not target a specific supervisor and code outside supervision calls this method. See
605    /// [`spawn`][super::spawn].
606    pub fn spawn(self) -> ChildId {
607        let Self { target, spec } = self;
608
609        match target {
610            BuilderTarget::Ambient => super::spawn(spec),
611            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
612        }
613    }
614
615    /// Spawns the nested supervisor onto the ambient supervisor, the nearest supervisor above the current process.
616    ///
617    /// This method works as [`ChildBuilder::spawn_sibling`] does.
618    ///
619    /// # Panics
620    ///
621    /// Panics if this builder does not target a specific supervisor and there is no ambient supervisor.
622    pub fn spawn_sibling(self) -> ChildId {
623        let Self { target, spec } = self;
624
625        match target {
626            BuilderTarget::Ambient => super::spawn_sibling(spec),
627            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
628        }
629    }

756        // The central promise of a one-shot worker: shutdown is a trigger, not an enforcement, so a worker that is
757        // still finishing when the drain starts gets to finish. A clean supervisor result is the assertion that
758        // matters -- `ShutdownTimedOut` would mean it was aborted instead.
