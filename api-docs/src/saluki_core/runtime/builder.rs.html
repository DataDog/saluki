1//! Builder for describing children.
2//!
3//! [`ChildSpecification`] is the complete description of a child, and this builder is the only way to configure one:
4//! the specification itself carries no public methods. The builder turns an asynchronous function, or a
5//! [`Supervisable`], into a child with sensible defaults, and uses the typestate pattern to expose only the settings
6//! that make sense for the kind of worker being described.
7//!
8//! It comes in matching ambient and explicit forms, mirroring the two ways to spawn: the free functions here
9//! ([`worker`], [`supervisable`]) target the ambient supervisor, and the identically named methods on
10//! [`SupervisorHandle`] target that handle's supervisor. Either way, [`ChildBuilder::spawn`] starts the child on a
11//! running supervisor, while [`ChildBuilder::build`] hands it to [`Supervisor::add_worker`][add_worker] to be started
12//! when that supervisor runs.
13//!
14//! [add_worker]: super::Supervisor::add_worker
15//!
16//! # Child lifecycle, and one-shot vs supervisable
17//!
18//! We classify tasks as either _one-shot_ or _supervisable_: one-shot tasks are those based on a provided closure,
19//! which cannot be reinitialized and so cannot be restarted, and supervisable tasks are those based on an
20//! implementation of [`Supervisable`], which allows for (potentially) initializing the underlying task future multiple
21//! times.
22//!
23//! One-shot tasks are always [`temporary`][RestartType::Temporary], since they cannot be reinitialized. Supervisable
24//! tasks are [`permanent`][RestartType::Permanent] by default, since their structure exposes a way to initialize the
25//! worker again; [`ChildBuilder::transient`] and [`ChildBuilder::temporary`] narrow that.
26//!
27//! All child tasks default to being marked as non-significant, so their termination -- clean or otherwise -- leaves
28//! the supervisor running. This is usually the correct behavior, but a supervisor that cannot function without a
29//! particular child may wish to mark it significant. See [`ChildBuilder::with_significant`], which is available only
30//! for a child whose restart policy lets it terminate for good; a permanent child is always brought back, so there is
31//! no termination for the supervisor to act on.
32//!
33//! # Shutdown
34//!
35//! A subtree shutdown is a _trigger_, not an enforcement. A one-shot child built with [`worker`] never receives the
36//! shutdown signal. It runs until it reaches its own terminal condition, and the supervisor waits for it. Examples of a
37//! terminal condition are an input channel that closes, a loop that finishes, and a request that completes.
38//!
39//! This behavior lets a set of tasks that are connected by channels drain in dependency order. The tasks do not have to
40//! know that order. Because of this behavior, it is not a problem that a one-shot child cannot see the shutdown signal.
41//!
42//! What bounds the wait is the supervisor's [shutdown budget][super::Supervisor::with_shutdown_budget], which covers
43//! the whole set of children rather than each guessing at how long it ought to take. A supervisor without a budget has
44//! nothing to bound such a child with, so it falls back to the worker's own strategy.
45//!
46//! Two cases need something other than the default:
47//!
48//! - Work with no terminal condition -- an endless background loop -- would hold the drain until the budget elapsed.
49//!   Give it [`ShutdownStrategy::Brutal`] via [`ChildBuilder::with_shutdown_strategy`] so it is aborted at once.
50//! - If work must observe shutdown to know that it must stop, or must run cleanup, build it with
51//!   [`worker_with_shutdown`]. The body of that worker receives the shutdown signal. You can also implement
52//!   [`Supervisable`] directly.
53//!
54//! [`ChildBuilder::with_shutdown_timeout`] imposes a deadline shorter than the budget when a particular child should
55//! be abandoned sooner than its siblings.
56//!
57//! # Children of the current process
58//!
59//! [`ChildBuilder::spawn`] makes a child a sibling of the current process, under the same supervisor.
60//! [`ChildBuilder::spawn_child`] makes the child a child of the current process instead, and the [scope][super::scope]
61//! of that process holds it. The process does not finish until its children finish. When the body of the process
62//! returns, the scope stops the children, each according to its own shutdown strategy. A supervisor's budget does not
63//! apply in a scope. [`ChildBuilder::needed`] marks a child that the process cannot work without.
64//!
65//! # Task naming
66//!
67//! Child task names should generally _not_ contain unique patterns/tokens -- such as monotonic IDs or high-cardinality
68//! values -- as they are used for internal telemetry about the task. Generally, task names should be thought of as a
69//! category label: if a supervisor manages tasks for handling connections, it should prefer to name them like
70//! `conn_handler` instead of `conn_handler_<ID or IP>`.
71

220    /// A [`Supervisor`] can be handed to [`spawn`][Self::spawn] or [`Supervisor::add_worker`] directly, which is all

250/// The kind of worker a [`ChildBuilder`] is describing.
251///
252/// This trait is sealed, and exists only to mark which configuration a builder makes available: a worker that can be
253/// initialized more than once accepts a restart policy, and one that can't doesn't. Implemented by [`OneShot`],
254/// [`Restartable`] and [`Terminable`].
255pub trait BuilderState: sealed::Sealed {}
256
257/// Marks a builder whose child can terminate without being restarted.
258///
259/// This trait is sealed, and exists only to gate [`ChildBuilder::with_significant`]: significance asks what the
260/// supervisor should do when a child terminates and isn't brought back, so it means nothing for a child that always
261/// is. Implemented by [`OneShot`] and [`Terminable`].
262pub trait CanTerminate: BuilderState {}
263
264/// Marks a builder whose worker can only be initialized once.
265///
266/// Closure-based children ([`SupervisorHandle::worker`]) consume their body when they start, so they can never be
267/// restarted: they are always [`RestartType::Temporary`], and no restart policy is offered.
268pub struct OneShot;
269
270/// Marks a builder whose worker can be initialized more than once.
271///
272/// A [`Supervisable`] builds its work in [`initialize`][Supervisable::initialize] each time it starts, so it can be
273/// restarted, and it is [`RestartType::Permanent`] unless narrowed with [`ChildBuilder::transient`] or
274/// [`ChildBuilder::temporary`].
275pub struct Restartable;
276
277/// Marks a builder whose worker can be initialized more than once but has been narrowed to a restart policy that lets
278/// it terminate for good.
279///
280/// Reached from [`Restartable`] via [`ChildBuilder::transient`] or [`ChildBuilder::temporary`]. Narrowing is one-way:
281/// there is no route back to [`Restartable`], which is what keeps a child from being marked significant and then
282/// widened to [`RestartType::Permanent`] behind the flag's back.
283pub struct Terminable;

294/// Builder for a yet-to-be-started child task.
295///
296/// This is the only way to configure a child: [`ChildSpecification`], which this produces, carries no settings of its
297/// own. The builder uses the typestate pattern to expose only the properties that make sense for the child being
298/// described, so an invalid combination doesn't need rejecting at runtime because it can't be written down. Two axes
299/// govern that: whether the worker can be initialized more than once (which decides whether a restart policy is
300/// offered), and whether its policy lets it terminate for good (which decides whether it can be marked significant).
301///
302/// See [`BuilderState`] and [`CanTerminate`] for the states themselves.
303#[must_use = "a child is only described until `spawn` or `build` is called"]
304pub struct ChildBuilder<'a, S = OneShot> {
305    target: BuilderTarget<'a>,
306    spec: ChildSpecification<WorkerSpec>,
307    _state: PhantomData<S>,
308}
309
310/// Which supervisor a [`ChildBuilder`] spawns onto.
311#[derive(Clone, Copy)]
312enum BuilderTarget<'a> {
313    /// Whichever supervisor is ambient when the child is spawned.
314    Ambient,
315
316    /// This specific supervisor.
317    Handle(&'a SupervisorHandle),
318}
319
320impl<'a, S: BuilderState> ChildBuilder<'a, S> {
321    fn new(target: BuilderTarget<'a>, spec: ChildSpecification<WorkerSpec>) -> Self {
322        Self {
323            target,
324            spec,
325            _state: PhantomData,
326        }
327    }
328
329    fn map_spec<F>(self, f: F) -> Self
330    where
331        F: FnOnce(ChildSpecification<WorkerSpec>) -> ChildSpecification<WorkerSpec>,
332    {
333        self.map_spec_into(f)
334    }
335
336    /// As [`map_spec`][Self::map_spec], but for a transition that also moves the builder to a different state.
337    fn map_spec_into<F, S2>(self, f: F) -> ChildBuilder<'a, S2>
338    where
339        F: FnOnce(ChildSpecification<WorkerSpec>) -> ChildSpecification<WorkerSpec>,
340        S2: BuilderState,
341    {
342        let Self { target, spec, .. } = self;
343
344        ChildBuilder::new(target, f(spec))
345    }
346
347    /// Runs this child task on a specific runtime.
348    ///
349    /// Use this for compute-heavy work -- encoding, serialization, protocol servers -- that shouldn't contend with the
350    /// runtime driving the supervisor and its I/O. Only where the task runs changes: the child is still supervised
351    /// here, and is still shut down and restarted by this supervisor.
352    pub fn on_runtime(self, handle: Handle) -> Self {
353        self.map_spec(|spec| spec.with_runtime(handle))
354    }
355
356    /// Sets an explicit shutdown timeout for this child task.
357    ///
358    /// By default a closure-based child has no deadline of its own and is bounded only by the supervisor's shutdown
359    /// budget. Set this when the supervisor wants a particular child abandoned sooner than that -- a deadline it is
360    /// deliberately imposing, rather than a guess at how long the child ought to take. A value longer than the budget
361    /// has no effect, since the two are resolved to whichever elapses first.
362    ///
363    /// A [scope] has no budget. A child spawned into a scope is held only to its own strategy, which for
364    /// a closure-based child is graceful with a timeout of five seconds unless this method sets another one.
365    ///
366    /// For a [`Supervisable`] child, this overrides the strategy the task reports for itself.
367    pub fn with_shutdown_timeout(self, timeout: Duration) -> Self {
368        self.with_shutdown_strategy(ShutdownStrategy::Graceful(timeout))
369    }
370
371    /// Sets the explicit shutdown strategy used for this child task.
372    pub fn with_shutdown_strategy(self, strategy: ShutdownStrategy) -> Self {
373        self.map_spec(|spec| spec.with_shutdown_strategy(strategy))
374    }
375
376    /// Gives this child no shutdown deadline of its own, leaving it bounded solely by the supervisor's shutdown
377    /// budget.
378    ///
379    /// This is already the default for a closure-based child. A [`Supervisable`] child reports its own strategy, so
380    /// this is how one opts into being bounded as part of the group instead -- without which it silently keeps
381    /// whatever [`Supervisable::shutdown_strategy`] returns, which may be far shorter than the budget.
382    ///
383    /// See [`Supervisor::with_shutdown_budget`][budget] for what the budget itself is. A [scope] has no budget, so a
384    /// child spawned into a scope keeps the strategy that it reports for itself.
385    ///
386    /// [budget]: super::Supervisor::with_shutdown_budget
387    pub fn with_budget_bounded_shutdown(self) -> Self {
388        self.map_spec(|spec| spec.with_budget_bounded_shutdown())
389    }
390
391    /// Finishes describing the child without starting it, for [`Supervisor::add_worker`].
392    ///
393    /// Use this to register a configured child on a supervisor that hasn't started yet; a child described this way is
394    /// started when the supervisor runs, and restarted with it. [`spawn`][Self::spawn] is the counterpart for a
395    /// supervisor that is already running.
396    ///
397    /// Whichever supervisor this builder was created against is irrelevant here -- the child belongs to whichever one
398    /// it is handed to.
399    ///
400    /// [`Supervisor::add_worker`]: super::Supervisor::add_worker
401    pub fn build(self) -> ChildSpecification<WorkerSpec> {
402        self.spec
403    }
404
405    /// Spawns the child.
406    ///
407    /// Returns the child's [`ChildId`]. The child is queued for the supervisor rather than started synchronously, so
408    /// it may not be running yet by the time this returns; if the supervisor isn't running, or shuts down before
409    /// reaching the child, it never runs at all.
410    ///
411    /// # Panics
412    ///
413    /// If this builder targets the ambient supervisor and there isn't one, this panics. See [`spawn`][super::spawn].
414    pub fn spawn(self) -> ChildId {
415        let Self { target, spec, .. } = self;
416
417        match target {
418            BuilderTarget::Ambient => super::spawn(spec),
419            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
420        }
421    }
422
423    /// Marks this child as one that its owner cannot work without.
424    ///
425    /// This setting applies when the child is spawned into a [scope][super::scope]. If the child terminates without a
426    /// request to stop, and its restart policy does not restart it, the process that owns the scope fails. The process
427    /// does not continue without the child. A supervisor ignores this setting and uses
428    /// [significance][ChildBuilder::with_significant] instead.
429    ///
430    /// The default is hosted. If a hosted child terminates and is not restarted, its owner reaps the child and
431    /// continues. In both cases, if a child stops more often than the restart limit of its scope allows, the owner
432    /// fails.
433    pub fn needed(self) -> Self {
434        self.map_spec(|spec| spec.with_edge(Edge::Needed))
435    }
436
437    /// Spawns the child into the scope of the current process, so that the child belongs to that process.
438    ///
439    /// [`spawn`][Self::spawn] makes the child a sibling of the current process, under the same supervisor. This method
440    /// is different: it makes the child a child of the current process itself. The process does not finish until the
441    /// child finishes. When the body of the process returns, the scope tells the child to stop. See
442    /// [`scope`][super::scope] for the details. The supervisor that this builder was created from has no effect here.
443    ///
444    /// # Panics
445    ///
446    /// Panics if there is no current scope. This means that the caller does not run in a supervised process. For code
447    /// that can run outside supervision, use [`spawn_child_or_detached`][Self::spawn_child_or_detached].
448    pub fn spawn_child(self) -> ChildId {
449        let Self { spec, .. } = self;
450
451        match scope::current() {
452            Some(scope) => scope.spawn(spec),
453            None => panic!(
454                "`spawn_child` called outside of a supervised process: there is no current scope to spawn into. Use \
455                 `spawn_child_or_detached` for code that may run outside supervision."
456            ),
457        }
458    }
459
460    /// Spawns the child into `scope`.
461    pub fn spawn_in(self, scope: &Scope) -> ChildId {
462        let Self { spec, .. } = self;
463
464        scope.spawn(spec)
465    }
466
467    /// Spawns the child into the scope of the current process, as [`spawn_child`][Self::spawn_child] does, or as a
468    /// detached task outside supervision.
469    ///
470    /// Returns the [`ChildId`] of the child, or `None` if there was no current scope and the child started as a
471    /// detached task instead. A detached child never receives a shutdown signal, and nothing restarts it or waits for
472    /// it. This is how the same work runs without scopes at all. Thus, this method is the correct choice for code that
473    /// can be called from any location, such as a primitive that a test can construct.
474    pub fn spawn_child_or_detached(self) -> Option<ChildId> {
475        let Self { spec, .. } = self;
476
477        match scope::current() {
478            Some(scope) => Some(scope.spawn(spec)),
479            None => {
480                scope::spawn_detached(spec, ShutdownHandle::noop());
481                None
482            }
483        }
484    }
485}

487impl<'a, S: CanTerminate> ChildBuilder<'a, S> {
488    /// Sets whether this child task's termination should stop the supervisor.
489    ///
490    /// Under [`AutoShutdown::AnySignificant`][auto_shutdown] -- which is what a topology component's supervisor uses
491    /// -- a significant child terminating **shuts the supervisor down**: the child is not individually restarted. That
492    /// happens even when the child exits cleanly, so this suits a child the supervisor cannot function without, and
493    /// not one that is expected to finish on its own.
494    ///
495    /// For example, a component handling client connections generally shouldn't stop just because one connection
496    /// failed, but a component forwarding work to a child task may become inoperable if that task dies and cannot be
497    /// reattached to the necessary channels or state without recreating the component.
498    ///
499    /// Offered only for a child that can actually terminate for good -- a one-shot child, or a supervisable one
500    /// narrowed with [`transient`][ChildBuilder::transient] or [`temporary`][ChildBuilder::temporary]. A permanent
501    /// child is always restarted and so never reaches this path, which makes marking one significant a contradiction
502    /// rather than a setting.
503    ///
504    /// Defaults to `false`.
505    ///
506    /// [auto_shutdown]: super::AutoShutdown::AnySignificant
507    pub fn with_significant(self, significant: bool) -> Self {
508        self.map_spec(|spec| spec.with_significant(significant))
509    }
510}

523impl<'a> ChildBuilder<'a, Restartable> {
524    fn restartable<T>(target: BuilderTarget<'a>, worker: T) -> Self
525    where
526        T: Supervisable + 'static,
527    {
528        Self::new(
529            target,
530            ChildSpecification::worker(worker).with_restart_type(RestartType::Permanent),
531        )
532    }
533
534    /// Restarts this child task only when it terminates abnormally.
535    ///
536    /// A clean exit is taken at face value and the child stays stopped; a failure is restarted. Use this for work that
537    /// has a natural end but whose failure means it never got there.
538    ///
539    /// Narrows the restart policy to [`RestartType::Transient`], which makes
540    /// [`with_significant`][ChildBuilder::with_significant] available: a child that can stop for good is one whose
541    /// termination the supervisor may want to act on.
542    pub fn transient(self) -> ChildBuilder<'a, Terminable> {
543        self.map_spec_into(|spec| spec.with_restart_type(RestartType::Transient))
544    }
545
546    /// Never restarts this child task.
547    ///
548    /// However it terminates -- cleanly or by failing -- the child stays stopped. Use this for work that is meant to
549    /// run once, where a retry would be wrong rather than merely redundant.
550    ///
551    /// Narrows the restart policy to [`RestartType::Temporary`], which makes
552    /// [`with_significant`][ChildBuilder::with_significant] available: a child that can stop for good is one whose
553    /// termination the supervisor may want to act on.
554    pub fn temporary(self) -> ChildBuilder<'a, Terminable> {
555        self.map_spec_into(|spec| spec.with_restart_type(RestartType::Temporary))
556    }
557}

559/// Builder for a yet-to-be-started nested supervisor.
560///
561/// The counterpart to [`ChildBuilder`] for a child that is itself a [`Supervisor`], and deliberately a much smaller
562/// surface. A nested supervisor has no placement of its own (it runs wherever its parent does, and its children carry
563/// their own placement) and no shutdown deadline of its own (it bounds its own drain through its children), so what
564/// is left to configure is the restart policy and significance.
565///
566/// Uses the same typestate as [`ChildBuilder`]: significance is offered only once the restart policy has been
567/// narrowed to one that lets the child terminate for good, since a permanent child is always brought back and so
568/// never has a termination for the parent to act on.
569#[must_use = "a child is only described until `spawn` or `build` is called"]
570pub struct NestedSupervisorBuilder<'a, S = Restartable> {
571    target: BuilderTarget<'a>,
572    spec: ChildSpecification<SupervisorSpec>,
573    _state: PhantomData<S>,
574}
575
576impl<'a, S: BuilderState> NestedSupervisorBuilder<'a, S> {
577    fn from_parts(target: BuilderTarget<'a>, spec: ChildSpecification<SupervisorSpec>) -> Self {
578        Self {
579            target,
580            spec,
581            _state: PhantomData,
582        }
583    }
584
585    /// As [`map_spec`][ChildBuilder::map_spec], but for a transition that also moves the builder to a different state.
586    fn map_spec_into<F, S2>(self, f: F) -> NestedSupervisorBuilder<'a, S2>
587    where
588        F: FnOnce(ChildSpecification<SupervisorSpec>) -> ChildSpecification<SupervisorSpec>,
589        S2: BuilderState,
590    {
591        let Self { target, spec, .. } = self;
592
593        NestedSupervisorBuilder::from_parts(target, f(spec))
594    }
595
596    /// Finishes describing the child without starting it, for [`Supervisor::add_worker`].
597    ///
598    /// Use this to register a configured subtree on a supervisor that hasn't started yet; [`spawn`][Self::spawn] is
599    /// the counterpart for a supervisor that is already running.
600    ///
601    /// Whichever supervisor this builder was created against is irrelevant here -- the child belongs to whichever one
602    /// it is handed to.
603    pub fn build(self) -> ChildSpecification<SupervisorSpec> {
604        self.spec
605    }
606
607    /// Spawns the nested supervisor.
608    ///
609    /// Returns the child's [`ChildId`]. As with [`ChildBuilder::spawn`], the child is queued rather than started
610    /// synchronously.
611    ///
612    /// # Panics
613    ///
614    /// If this builder targets the ambient supervisor and there isn't one, this panics. See [`spawn`][super::spawn].
615    pub fn spawn(self) -> ChildId {
616        let Self { target, spec, .. } = self;
617
618        match target {
619            BuilderTarget::Ambient => super::spawn(spec),
620            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
621        }
622    }
623}
624
625impl<'a> NestedSupervisorBuilder<'a, Restartable> {
626    fn new(target: BuilderTarget<'a>, supervisor: Supervisor) -> Self {
627        Self::from_parts(
628            target,
629            ChildSpecification::from(supervisor).with_restart_type(RestartType::Permanent),
630        )
631    }
632
633    /// Restarts this subtree only when it terminates abnormally.
634    ///
635    /// Narrows the restart policy to [`RestartType::Transient`], which makes
636    /// [`with_significant`][NestedSupervisorBuilder::with_significant] available.
637    pub fn transient(self) -> NestedSupervisorBuilder<'a, Terminable> {
638        self.map_spec_into(|spec| spec.with_restart_type(RestartType::Transient))
639    }
640
641    /// Never restarts this subtree.
642    ///
643    /// Narrows the restart policy to [`RestartType::Temporary`], which makes
644    /// [`with_significant`][NestedSupervisorBuilder::with_significant] available.
645    pub fn temporary(self) -> NestedSupervisorBuilder<'a, Terminable> {
646        self.map_spec_into(|spec| spec.with_restart_type(RestartType::Temporary))
647    }
648}
649
650impl<S: CanTerminate> NestedSupervisorBuilder<'_, S> {
651    /// Sets whether this subtree's termination should stop the parent supervisor.
652    ///
653    /// See [`ChildBuilder::with_significant`], which this mirrors.
654    pub fn with_significant(self, significant: bool) -> Self {
655        self.map_spec_into(|spec| spec.with_significant(significant))
656    }
657}

693            let thread_id = Arc::new(Mutex::new(None));
694            let initializations = Arc::new(AtomicUsize::new(0));

772        // The central promise of a one-shot worker: shutdown is a trigger, not an enforcement, so a worker that is
773        // still finishing when the drain starts gets to finish. A clean supervisor result is the assertion that
