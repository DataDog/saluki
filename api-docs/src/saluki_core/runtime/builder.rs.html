1//! Builder for describing children.
2//!
3//! [`ChildSpecification`] is the complete description of a child, and this builder is the only way to configure one:
4//! the specification itself carries no public methods. The builder turns an asynchronous function, or a
5//! [`Supervisable`], into a child with sensible defaults, and uses the typestate pattern to expose only the settings
6//! that make sense for the kind of worker being described.
7//!
8//! It comes in matching ambient and explicit forms, mirroring the two ways to spawn: the free functions here
9//! ([`worker`], [`supervisable`]) target the ambient supervisor, and the identically named methods on
10//! [`SupervisorHandle`] target that handle's supervisor. Either way, [`ChildBuilder::spawn`] starts the child on a
11//! running supervisor, while [`ChildBuilder::build`] hands it to [`Supervisor::add_worker`][add_worker] to be started
12//! when that supervisor runs.
13//!
14//! [add_worker]: super::Supervisor::add_worker
15//!
16//! # Child lifecycle, and one-shot vs supervisable
17//!
18//! We classify tasks as either _one-shot_ or _supervisable_: one-shot tasks are those based on a provided closure,
19//! which cannot be reinitialized and so cannot be restarted, and supervisable tasks are those based on an
20//! implementation of [`Supervisable`], which allows for (potentially) initializing the underlying task future multiple
21//! times.
22//!
23//! One-shot tasks are always [`temporary`][RestartType::Temporary], since they cannot be reinitialized. Supervisable
24//! tasks are [`permanent`][RestartType::Permanent] by default, since their structure exposes a way to initialize the
25//! worker again; [`ChildBuilder::transient`] and [`ChildBuilder::temporary`] narrow that.
26//!
27//! All child tasks default to being marked as non-significant, so their termination -- clean or otherwise -- leaves
28//! the supervisor running. This is usually the correct behavior, but a supervisor that cannot function without a
29//! particular child may wish to mark it significant. See [`ChildBuilder::with_significant`], which is available only
30//! for a child whose restart policy lets it terminate for good; a permanent child is always brought back, so there is
31//! no termination for the supervisor to act on.
32//!
33//! # Shutdown
34//!
35//! Shutting a subtree down is a _trigger_, not an enforcement. A one-shot child is never handed the shutdown signal at
36//! all: it runs until it reaches its own terminal condition -- an input channel closing, a loop finishing, a request
37//! completing -- and the supervisor waits for it. That is what lets a set of tasks connected by channels drain in
38//! dependency order without any of them having to know that order, and it is why the shutdown signal being invisible
39//! here costs nothing.
40//!
41//! What bounds the wait is the supervisor's [shutdown budget][super::Supervisor::with_shutdown_budget], which covers
42//! the whole set of children rather than each guessing at how long it ought to take. A supervisor without a budget has
43//! nothing to bound such a child with, so it falls back to the worker's own strategy.
44//!
45//! Two cases need something other than the default:
46//!
47//! - Work with no terminal condition -- an endless background loop -- would hold the drain until the budget elapsed.
48//!   Give it [`ShutdownStrategy::Brutal`] via [`ChildBuilder::with_shutdown_strategy`] so it is aborted at once.
49//! - Work that must observe shutdown to know it should stop, or that needs to run cleanup, isn't a one-shot worker at
50//!   all: implement [`Supervisable`] directly, which does receive the signal.
51//!
52//! [`ChildBuilder::with_shutdown_timeout`] imposes a deadline shorter than the budget when a particular child should
53//! be abandoned sooner than its siblings.
54//!
55//! # Task naming
56//!
57//! Child task names should generally _not_ contain unique patterns/tokens -- such as monotonic IDs or high-cardinality
58//! values -- as they are used for internal telemetry about the task. Generally, task names should be thought of as a
59//! category label: if a supervisor manages tasks for handling connections, it should prefer to name them like
60//! `conn_handler` instead of `conn_handler_<ID or IP>`.

71/// Creates a builder for a child task on the ambient supervisor.
72///
73/// The ambient counterpart to [`SupervisorHandle::worker`].
74///
75/// # Panics
76///
77/// [`ChildBuilder::spawn`] panics if there is no ambient supervisor. See [`spawn`][super::spawn].
78pub fn worker<N, Fut>(name: N, fut: Fut) -> ChildBuilder<'static>
79where
80    N: Into<String>,
81    Fut: Future + Send + 'static,
82    Fut::Output: IntoWorkerResult,
83{
84    ChildBuilder::one_shot(BuilderTarget::Ambient, FnWorker::new(name, fut))
85}

87/// Creates a builder for a supervisable child task on the ambient supervisor.
88///
89/// The ambient counterpart to [`SupervisorHandle::supervisable`], which documents what a supervisable task is.
90///
91/// # Panics
92///
93/// [`ChildBuilder::spawn`] panics if there is no ambient supervisor. See [`spawn`][super::spawn].
94pub fn supervisable<T>(worker: T) -> ChildBuilder<'static, Restartable>

101impl SupervisorHandle {
102    /// Creates a builder for a child task built from a plain future.
103    ///
104    /// The task runs until it reaches its own terminal condition; it is never handed the shutdown signal. See
105    /// [`FnWorker`] for what that means at shutdown, and for the two cases that need something else.
106    ///
107    /// Use this method when advanced configuration of the underlying task is required. Otherwise, prefer
108    /// [`spawn_worker`][Self::spawn_worker].
109    ///
110    /// # Examples
111    ///
112    /// ```no_run
113    /// # use saluki_core::runtime::SupervisorHandle;
114    /// # async fn encode() {}
115    /// # fn example(supervisor: &SupervisorHandle, pool: tokio::runtime::Handle) {
116    /// supervisor.worker("encoder", encode()).on_runtime(pool).spawn();
117    /// # }
118    /// ```
119    pub fn worker<N, Fut>(&self, name: N, fut: Fut) -> ChildBuilder<'_>
120    where
121        N: Into<String>,
122        Fut: Future + Send + 'static,
123        Fut::Output: IntoWorkerResult,
124    {
125        ChildBuilder::one_shot(BuilderTarget::Handle(self), FnWorker::new(name, fut))
126    }
127
128    /// Creates a builder for a supervisable child task.
129    ///
130    /// Supervisable tasks are those where the worker already implements [`Supervisable`], which lets the builder serve
131    /// as a consistent control surface for spawning both arbitrary asynchronous functions and more full-fledged
132    /// workers.
133    ///
134    /// Supervisable tasks are set to permanently restart by default.
135    ///
136    /// Use this method when advanced configuration of the underlying task is required. Otherwise, prefer
137    /// [`spawn_supervisable`][Self::spawn_supervisable].
138    pub fn supervisable<T>(&self, worker: T) -> ChildBuilder<'_, Restartable>
139    where
140        T: Supervisable + 'static,
141    {
142        ChildBuilder::restartable(BuilderTarget::Handle(self), worker)
143    }
144
145    /// Spawns a child task built from a plain future.
146    ///
147    /// The task runs until it reaches its own terminal condition; it is never handed the shutdown signal. See
148    /// [`FnWorker`] for what that means at shutdown, and for the two cases that need something else.
149    ///
150    /// Use [`worker`][Self::worker] when advanced configuration of the underlying task is required.
151    pub fn spawn_worker<N, Fut>(&self, name: N, fut: Fut) -> ChildId
152    where
153        N: Into<String>,
154        Fut: Future + Send + 'static,
155        Fut::Output: IntoWorkerResult,
156    {
157        self.worker(name, fut).spawn()
158    }
159
160    /// Spawns a supervisable child task.
161    ///
162    /// Supervisable tasks are those where the worker already implements [`Supervisable`], which lets the builder serve
163    /// as a consistent control surface for spawning both arbitrary asynchronous functions and more full-fledged
164    /// workers.
165    ///
166    /// Use [`supervisable`][Self::supervisable] when advanced configuration of the underlying task is required.
167    pub fn spawn_supervisable<T>(&self, worker: T) -> ChildId
168    where
169        T: Supervisable + 'static,
170    {
171        self.supervisable(worker).spawn()
172    }
173}

179/// The kind of worker a [`ChildBuilder`] is describing.
180///
181/// This trait is sealed, and exists only to mark which configuration a builder makes available: a worker that can be
182/// initialized more than once accepts a restart policy, and one that can't doesn't. Implemented by [`OneShot`],
183/// [`Restartable`] and [`Terminable`].
184pub trait BuilderState: sealed::Sealed {}
185
186/// Marks a builder whose child can terminate without being restarted.
187///
188/// This trait is sealed, and exists only to gate [`ChildBuilder::with_significant`]: significance asks what the
189/// supervisor should do when a child terminates and isn't brought back, so it means nothing for a child that always
190/// is. Implemented by [`OneShot`] and [`Terminable`].
191pub trait CanTerminate: BuilderState {}
192
193/// Marks a builder whose worker can only be initialized once.
194///
195/// Closure-based children ([`SupervisorHandle::worker`]) consume their body when they start, so they can never be
196/// restarted: they are always [`RestartType::Temporary`], and no restart policy is offered.
197pub struct OneShot;
198
199/// Marks a builder whose worker can be initialized more than once.
200///
201/// A [`Supervisable`] builds its work in [`initialize`][Supervisable::initialize] each time it starts, so it can be
202/// restarted, and it is [`RestartType::Permanent`] unless narrowed with [`ChildBuilder::transient`] or
203/// [`ChildBuilder::temporary`].
204pub struct Restartable;
205
206/// Marks a builder whose worker can be initialized more than once but has been narrowed to a restart policy that lets
207/// it terminate for good.
208///
209/// Reached from [`Restartable`] via [`ChildBuilder::transient`] or [`ChildBuilder::temporary`]. Narrowing is one-way:
210/// there is no route back to [`Restartable`], which is what keeps a child from being marked significant and then
211/// widened to [`RestartType::Permanent`] behind the flag's back.
212pub struct Terminable;

223/// Builder for a yet-to-be-started child task.
224///
225/// This is the only way to configure a child: [`ChildSpecification`], which this produces, carries no settings of its
226/// own. The builder uses the typestate pattern to expose only the properties that make sense for the child being
227/// described, so an invalid combination doesn't need rejecting at runtime because it can't be written down. Two axes
228/// govern that: whether the worker can be initialized more than once (which decides whether a restart policy is
229/// offered), and whether its policy lets it terminate for good (which decides whether it can be marked significant).
230///
231/// See [`BuilderState`] and [`CanTerminate`] for the states themselves.
232#[must_use = "a child is only described until `spawn` or `build` is called"]
233pub struct ChildBuilder<'a, S = OneShot> {
234    target: BuilderTarget<'a>,
235    spec: ChildSpecification<WorkerSpec>,
236    _state: PhantomData<S>,
237}
238
239/// Which supervisor a [`ChildBuilder`] spawns onto.
240#[derive(Clone, Copy)]
241enum BuilderTarget<'a> {
242    /// Whichever supervisor is ambient when the child is spawned.
243    Ambient,
244
245    /// This specific supervisor.
246    Handle(&'a SupervisorHandle),
247}
248
249impl<'a, S: BuilderState> ChildBuilder<'a, S> {
250    fn new(target: BuilderTarget<'a>, spec: ChildSpecification<WorkerSpec>) -> Self {
251        Self {
252            target,
253            spec,
254            _state: PhantomData,
255        }
256    }
257
258    fn map_spec<F>(self, f: F) -> Self
259    where
260        F: FnOnce(ChildSpecification<WorkerSpec>) -> ChildSpecification<WorkerSpec>,
261    {
262        self.map_spec_into(f)
263    }
264
265    /// As [`map_spec`][Self::map_spec], but for a transition that also moves the builder to a different state.
266    fn map_spec_into<F, S2>(self, f: F) -> ChildBuilder<'a, S2>
267    where
268        F: FnOnce(ChildSpecification<WorkerSpec>) -> ChildSpecification<WorkerSpec>,
269        S2: BuilderState,
270    {
271        let Self { target, spec, .. } = self;
272
273        ChildBuilder::new(target, f(spec))
274    }
275
276    /// Runs this child task on a specific runtime.
277    ///
278    /// Use this for compute-heavy work -- encoding, serialization, protocol servers -- that shouldn't contend with the
279    /// runtime driving the supervisor and its I/O. Only where the task runs changes: the child is still supervised
280    /// here, and is still shut down and restarted by this supervisor.
281    pub fn on_runtime(self, handle: Handle) -> Self {
282        self.map_spec(|spec| spec.with_runtime(handle))
283    }
284
285    /// Sets an explicit shutdown timeout for this child task.
286    ///
287    /// By default a closure-based child has no deadline of its own and is bounded only by the supervisor's shutdown
288    /// budget. Set this when the supervisor wants a particular child abandoned sooner than that -- a deadline it is
289    /// deliberately imposing, rather than a guess at how long the child ought to take. A value longer than the budget
290    /// has no effect, since the two are resolved to whichever elapses first.
291    ///
292    /// For a [`Supervisable`] child, this overrides the strategy the task reports for itself.
293    pub fn with_shutdown_timeout(self, timeout: Duration) -> Self {
294        self.with_shutdown_strategy(ShutdownStrategy::Graceful(timeout))
295    }
296
297    /// Sets the explicit shutdown strategy used for this child task.
298    pub fn with_shutdown_strategy(self, strategy: ShutdownStrategy) -> Self {
299        self.map_spec(|spec| spec.with_shutdown_strategy(strategy))
300    }
301
302    /// Gives this child no shutdown deadline of its own, leaving it bounded solely by the supervisor's shutdown
303    /// budget.
304    ///
305    /// This is already the default for a closure-based child. A [`Supervisable`] child reports its own strategy, so
306    /// this is how one opts into being bounded as part of the group instead -- without which it silently keeps
307    /// whatever [`Supervisable::shutdown_strategy`] returns, which may be far shorter than the budget.
308    ///
309    /// See [`Supervisor::with_shutdown_budget`][budget] for what the budget itself is.
310    ///
311    /// [budget]: super::Supervisor::with_shutdown_budget
312    pub fn with_budget_bounded_shutdown(self) -> Self {
313        self.map_spec(|spec| spec.with_budget_bounded_shutdown())
314    }
315
316    /// Finishes describing the child without starting it, for [`Supervisor::add_worker`].
317    ///
318    /// Use this to register a configured child on a supervisor that hasn't started yet; a child described this way is
319    /// started when the supervisor runs, and restarted with it. [`spawn`][Self::spawn] is the counterpart for a
320    /// supervisor that is already running.
321    ///
322    /// Whichever supervisor this builder was created against is irrelevant here -- the child belongs to whichever one
323    /// it is handed to.
324    ///
325    /// [`Supervisor::add_worker`]: super::Supervisor::add_worker
326    pub fn build(self) -> ChildSpecification<WorkerSpec> {
327        self.spec
328    }
329
330    /// Spawns the child.
331    ///
332    /// Returns the child's [`ChildId`]. The child is queued for the supervisor rather than started synchronously, so
333    /// it may not be running yet by the time this returns; if the supervisor isn't running, or shuts down before
334    /// reaching the child, it never runs at all.
335    ///
336    /// # Panics
337    ///
338    /// If this builder targets the ambient supervisor and there isn't one, this panics. See [`spawn`][super::spawn].
339    pub fn spawn(self) -> ChildId {
340        let Self { target, spec, .. } = self;
341
342        match target {
343            BuilderTarget::Ambient => super::spawn(spec),
344            BuilderTarget::Handle(supervisor) => supervisor.spawn(spec),
345        }
346    }
347}

349impl<'a, S: CanTerminate> ChildBuilder<'a, S> {
350    /// Sets whether this child task's termination should stop the supervisor.
351    ///
352    /// Under [`AutoShutdown::AnySignificant`][auto_shutdown] -- which is what a topology component's supervisor uses
353    /// -- a significant child terminating **shuts the supervisor down**: the child is not individually restarted. That
354    /// happens even when the child exits cleanly, so this suits a child the supervisor cannot function without, and
355    /// not one that is expected to finish on its own.
356    ///
357    /// For example, a component handling client connections generally shouldn't stop just because one connection
358    /// failed, but a component forwarding work to a child task may become inoperable if that task dies and cannot be
359    /// reattached to the necessary channels or state without recreating the component.
360    ///
361    /// Offered only for a child that can actually terminate for good -- a one-shot child, or a supervisable one
362    /// narrowed with [`transient`][ChildBuilder::transient] or [`temporary`][ChildBuilder::temporary]. A permanent
363    /// child is always restarted and so never reaches this path, which makes marking one significant a contradiction
364    /// rather than a setting.
365    ///
366    /// Defaults to `false`.
367    ///
368    /// [auto_shutdown]: super::AutoShutdown::AnySignificant
369    pub fn with_significant(self, significant: bool) -> Self {
370        self.map_spec(|spec| spec.with_significant(significant))
371    }
372}

374impl<'a> ChildBuilder<'a, OneShot> {
375    fn one_shot<T>(target: BuilderTarget<'a>, worker: T) -> Self
376    where
377        T: Supervisable + 'static,
378    {
379        let spec = ChildSpecification::one_shot_worker(worker).with_budget_bounded_shutdown();
380
381        Self::new(target, spec)
382    }
383}
384
385impl<'a> ChildBuilder<'a, Restartable> {
386    fn restartable<T>(target: BuilderTarget<'a>, worker: T) -> Self
387    where
388        T: Supervisable + 'static,
389    {
390        Self::new(
391            target,
392            ChildSpecification::worker(worker).with_restart_type(RestartType::Permanent),
393        )
394    }
395
396    /// Restarts this child task only when it terminates abnormally.
397    ///
398    /// A clean exit is taken at face value and the child stays stopped; a failure is restarted. Use this for work that
399    /// has a natural end but whose failure means it never got there.
400    ///
401    /// Narrows the restart policy to [`RestartType::Transient`], which makes
402    /// [`with_significant`][ChildBuilder::with_significant] available: a child that can stop for good is one whose
403    /// termination the supervisor may want to act on.
404    pub fn transient(self) -> ChildBuilder<'a, Terminable> {
405        self.map_spec_into(|spec| spec.with_restart_type(RestartType::Transient))
406    }
407
408    /// Never restarts this child task.
409    ///
410    /// However it terminates -- cleanly or by failing -- the child stays stopped. Use this for work that is meant to
411    /// run once, where a retry would be wrong rather than merely redundant.
412    ///
413    /// Narrows the restart policy to [`RestartType::Temporary`], which makes
414    /// [`with_significant`][ChildBuilder::with_significant] available: a child that can stop for good is one whose
415    /// termination the supervisor may want to act on.
416    pub fn temporary(self) -> ChildBuilder<'a, Terminable> {
417        self.map_spec_into(|spec| spec.with_restart_type(RestartType::Temporary))
418    }
419}

446    /// A hand-written [`Supervisable`] that records where and how often it was initialized, then runs until shutdown.

532    #[tokio::test]
533    async fn worker_drains_to_its_terminal_condition_before_the_supervisor_stops() {
534        // The central promise of a one-shot worker: shutdown is a trigger, not an enforcement, so a worker that is
535        // still finishing when the drain starts gets to finish. A clean supervisor result is the assertion that
536        // matters -- `ShutdownTimedOut` would mean it was aborted instead.
537        let supervisor = TestComponentSupervisor::start("test_component").await;
538
539        // The child does real work *after* its input closes, so it would be cut short if children were given a
540        // near-zero deadline rather than being bounded by the supervisor's budget.
541        let drained = Arc::new(AtomicUsize::new(0));
542        let child_drained = Arc::clone(&drained);
543        let (input_tx, input_rx) = oneshot::channel::<()>();
544
545        supervisor.handle().spawn_worker("drainer", async move {
546            let _ = input_rx.await;
547            tokio::time::sleep(DRAIN_DURATION).await;
548            child_drained.fetch_add(1, Ordering::SeqCst);
549        });
550
551        supervisor.wait_for_children(1).await;
552
553        // Close the child's input, then immediately shut down while it is still draining.
554        drop(input_tx);
555        let result = supervisor.shutdown().await;
556        assert!(
557            result.is_ok(),
558            "child should have drained rather than been aborted: {result:?}"
559        );
560        assert_eq!(drained.load(Ordering::SeqCst), 1);
561    }

593        // child is aborted when the budget elapses.
594        //
595        // This deliberately does not try to distinguish that from a child having silently fallen back to the
596        // `Supervisable` trait default of five seconds: deadlines resolve to whichever elapses first, so any budget
597        // under five seconds produces an identical result.
598        let supervisor = TestComponentSupervisor::start_with_budget("test_component", Duration::from_millis(200)).await;
599
600        supervisor.handle().spawn_worker("stuck", std::future::pending::<()>());
601        supervisor.wait_for_children(1).await;
602
603        let started = tokio::time::Instant::now();
604        let result = supervisor.shutdown().await;
605        let elapsed = started.elapsed();
606
607        assert!(
608            matches!(result, Err(SupervisorError::ShutdownTimedOut { aborted: 1 })),
609            "the budget should have aborted the stuck child, got {result:?}"
610        );
611        assert!(
612            elapsed < Duration::from_secs(1),
613            "the child should have been bounded by the 200ms budget rather than a deadline of its own; took {elapsed:?}"
614        );
615    }

733        // A `Supervisable` child goes through the same builder, including runtime placement.
734        let worker_pool_thread_id = Arc::new(Mutex::new(None));
735        let worker_pool_thread_id2 = Arc::clone(&worker_pool_thread_id);
736
737        let pool = tokio::runtime::Builder::new_multi_thread()
738            .worker_threads(1)
739            .on_thread_start(move || {
740                worker_pool_thread_id2
741                    .lock()
742                    .unwrap()
743                    .replace(std::thread::current().id());
744            })
745            .enable_all()
746            .build()
747            .expect("should build pool");
748
749        let supervisor = TestComponentSupervisor::start("test_component").await;
750
751        let (worker, initializations, worker_thread_id) = CountingWorker::new("counting");
752        supervisor
753            .handle()
754            .supervisable(worker)
755            .on_runtime(pool.handle().clone())
756            .spawn();
757
758        // `spawn` returns once the child is queued, and `initialize` runs inside the child's own task -- on the pool's
759        // runtime here -- so wait for it rather than assuming it has been polled.
760        supervisor.wait_for_children(1).await;
761        wait_until("the worker has initialized once", || {
762            initializations.load(Ordering::SeqCst) == 1
763        })
764        .await;
765

767        // would still pass.
768        let worker_pool_thread_id = worker_pool_thread_id
769            .lock()
770            .unwrap()
771            .expect("worker pool thread should have recorded its thread ID");
772        let worker_thread_id = worker_thread_id
773            .lock()
774            .unwrap()
775            .expect("worker should have recorded its thread ID");
776        assert_eq!(
777            worker_pool_thread_id, worker_thread_id,
778            "child should have run on the given runtime"
779        );
780
781        assert!(supervisor.shutdown().await.is_ok());
782        pool.shutdown_background();
783    }
