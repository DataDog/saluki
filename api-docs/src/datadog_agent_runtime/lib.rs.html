1//! Shared runtime infrastructure for a process that acts as a remote agent for the Datadog Agent.
2//!
3//! A remote agent is a process that runs alongside the Datadog Agent and attaches to it over the Remote Agent Registry
4//! (RAR): it registers itself, receives its configuration from the Agent, and serves the status, flare, and telemetry
5//! services that the Agent queries. This crate provides those pieces, so that each remote agent only supplies what is
6//! truly its own.
7//!
8//! # Conventions
9//!
10//! Constructors don't spawn tasks. Long-running work is returned as a
11//! [`Supervisable`][saluki_core::runtime::Supervisable] worker or [`Supervisor`][saluki_core::runtime::Supervisor] for
12//! the caller to place in its supervision tree.
13//!
14//! [`RemoteAgentBootstrap`][remote_agent::RemoteAgentBootstrap] is the one exception for now. Registration has to
15//! finish before the supervision tree exists, so [`RemoteAgentBootstrap::new`][remote_agent::RemoteAgentBootstrap::new]
16//! spawns the registration loop, and
17//! [`RemoteAgentBootstrap::create_config_stream`][remote_agent::RemoteAgentBootstrap::create_config_stream] spawns the
18//! configuration stream loop. Neither task is supervised, and neither stops on shutdown.
19//!
20//! Each subsystem that talks to the Datadog Agent opens its own connection with
21//! [`RemoteAgentClient::connect`][datadog_agent_commons::ipc::client::RemoteAgentClient::connect], rather than sharing a
22//! clone of another subsystem's client.
23//!
24//! # Features
25//!
26//! - `taskdump`: includes a Tokio task dump (`runtime-dump.txt`) in flares. Tokio only supports task dumps on Linux, on
27//!   `aarch64`, `x86`, `x86_64`, and `s390x`, so the feature does nothing on any other target. On those targets, the
28//!   build also requires `--cfg tokio_unstable`.
