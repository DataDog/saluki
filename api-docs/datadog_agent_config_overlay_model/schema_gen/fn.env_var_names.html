pub fn env_var_names(key: &str, info: Option<&FieldInfo>) -> Vec<String>
Expand description

The environment variables the Agent reads for the setting at key, highest priority first.

Explicit env_vars are used verbatim, in declared order. Otherwise each former name derives a name ahead of the key’s own, as BindEnvAndSetDefaultWithDeprecation binds them. A no-env setting, or a key without schema metadata, derives only its own name.

Panics when a setting has both env_vars and renamed_from. The environment reader calls this only for modeled settings, so only those fail the build.
