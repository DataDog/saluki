A program

A program is the whole metrics path after the sources: what happens to every metric between where it enters and where it is delivered. It is one policy metrics { ... } block of edges and nodes. Metrics enter at the scope's inputs, flow along edges through nodes, and every path ends by delivering (emit) or discarding (drop).

The quickest start is the editor's Load default program, which shows what ADP runs now, with comments, and changing it. Compiling shows every problem at its place in the text, and what would change.


      


      

        
Statements

        
Whitespace and line breaks do not matter. # starts a comment that runs to the end of the line.
          The order of statements does not matter either: the program is a graph.

        

          
StatementMeaning

          
            
input.<name> -> <target>
              Where one source's metrics enter. The inputs this ADP has are listed below.

            
node <id> = <operator>(<param>: <value>, ...) { <edges> }
              A step. The ID is yours: a lowercase letter, then up to 62 lowercase letters, digits, and single
                underscores between them (drop_debug, not dropDebug or
                drop__debug). An operator without parameters takes no parentheses, and a node without
                edges no block.

            
<port> -> <target>, inside a node's block
              An edge from one of the node's output ports. A node with one output port may leave it out:
                -> <target>.

            
<node>.<port> -> <target>
              The same edge, as a statement of its own.

          
        

        
Targets

        

          
            
<node>, <node>.<port>
              Another node. The port may be left out when the node has one input port; a merge's
                are numbered: joined.0.

            
emit to [<recipient>, ...]
              Deliver to recipients of the directory: a bare name such as
                primary, or an endpoint's URL in quotes. ADP adds the output that delivers to exactly
                those recipients.

            
emit <output>
              Deliver to an output ADP declares, by its ID.

            
dropDiscard.

          
        

        
An inline emit or drop is a node of its own, named after its parent and port:
          split port true leading to drop is the node
          <split>_true. Diagnostics and the plan diff use those names.

        
Short forms

        
    
          
  • An operator whose only parameter is a predicate takes it bare:
            split(name starts_with "a.") { true -> ... false -> ... }.
    • 
          
  • tee without parentheses numbers its branches in order:
            tee { -> a -> b } is tee(ports: 2) { 0 -> a 1 -> b }.

Values

        

          
WriteFor

          
            
"text", with \" \\ \n \t
              \u{1f600}A string. Always in double quotes, even where a name would do.

            
42, -7, 1.5A number.

            
500ms, 10s, 5m, 1h (also us,
              ns)
              A duration, in canonical form: the largest unit that writes it exactly, so
                5m, never 300s.

            
true, false, nullThe same.

            
[a, b]A list. A trailing comma is fine.

            
{ name: "x", limit: 3 }A record, such as one rule of a list of rules. Member
              names may be bare or quoted.

            
config("<binding>")
              A value read from ADP's configuration as it runs: one of the bindings a
                program may read, where the parameter allows it.

            
blob("sha256:...")A value kept in the program's blob table.

          
        

      


      

        
Predicates

        
What a split tests. String tests are ==, starts_with,
          in [...], and prefix_in [...]; they apply to name,
          intake_name, host, tag("k"), and origin_tag("k").

Operators

        
Every node names one of these. A parameter marked config may also read one of
          the bindings a program may read with config("..."); ? marks one
          that may be left out.

        

      


      

        
Recipes

        
Edits to the default program for common needs. Each one is a node between enrichment and the policy
          tee, metrics_policy, where the default program's comment says to route.

        

      


      

        
Rules

        
What compiling checks, beyond the grammar. An error refuses the program; a
          warning lets it through. These are the ones you are most likely to meet.
